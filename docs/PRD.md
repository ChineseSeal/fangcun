# 1. 产品概述

## 1.1 产品背景

传统中国印章兼具文字、书法、篆刻、章法、材质和历史文化等多重属性。

现有网络上的"印章生成器"大多停留在五个步骤：

1. 输入文字；
2. 调用篆书字体；
3. 放入方形边框；
4. 添加红色；
5. 输出 PNG。

这类产品解决的是"生成一个看起来像印章的图片"，却没有真正解决：

> 如何生成一枚具有传统篆刻审美、章法逻辑和历史风格的中国印章。

真正的传统篆刻并非简单的字体排版。一枚好的印章涉及：字法、篆法、章法、刀法、边框、疏密、朱白关系、残损、印泥、印面、印材、历史风格。

## 1.2 现存产品的四个断层

| 断层 | 现象 | 方寸的回答 |
|---|---|---|
| 字形断层 | 用一套现代篆书字体套所有字，忽略同一字在不同时代、不同印式下有不同写法 | 独立 Glyph 变体数据库（[9.5](#95-篆字数据库)） |
| 章法断层 | 等距 Grid 排版，不理解疏密、借边、留红、回文 | 章法引擎与评分函数（[9.7](#97-章法引擎)） |
| 质感断层 | 一张固定噪点贴图，结果高度重复 | 多尺度印蜕引擎（[9.9](#99-印蜕模拟系统)） |
| **认知断层** | 用户不知道自己生成的是什么，无法判断好坏，也学不到东西 | **印章知识普及体系（[第 10 章](#10-印章知识普及体系)）** |

前三个断层决定产品能不能做出"像样的印"；第四个断层决定用户能不能**看懂**、**选对**、**留下来**。V2.0 把第四个断层的解法提升为一等公民。

## 1.3 产品要解决的核心问题

| 编号 | 问题 | 目标用户 |
|---|---|---|
| P1 | 我想要一枚好看且"对"的中国印章，但不懂篆刻 | 普通用户 |
| P2 | 我需要可用于设计稿 / 印刷的矢量印章素材 | 设计师 |
| P3 | 我要给书画作品配一枚合规、得体的用印 | 书画用户 |
| P4 | 我要查字、参考古印、排印稿、辅助刻石 | 篆刻爱好者 |
| P5 | 我要在自己的产品里批量生成印章 | 开发者 |
| P6 | **我想真正搞懂中国印章是怎么回事** | **全部用户** |

# 2. 产品定位与愿景

## 2.1 产品定位

**方寸是一款中国传统印章设计与数字篆刻平台，同时是一套面向大众的印章知识普及系统。**

用户既可以在几秒钟内生成一枚传统印章，也可以像篆刻师一样对字形、章法、边框、残损、印泥和材质进行精细调整；在这个过程中，产品会持续解释"你正在做的事情在传统篆刻里叫什么、为什么这样做"。

方寸不是：

> 一个"篆书字体套边框"的印章生成器。

而是：

> 一个数字时代的篆刻工作台 + 一座人人可进的印章博物馆与学堂。

## 2.2 产品愿景

通过数字技术重新表达中国传统印章文化，让任何人都能够**理解、设计和拥有**一枚真正具有中国传统审美的印章。

长期目标：

> 建立全球最大的中文传统印章数字设计平台、篆刻字形数据库与印章知识体系。

## 2.3 一句话产品定义

> **方寸，是一个让任何人都能够设计、理解和拥有一枚真正中国印章的数字篆刻平台。**

注意定义中的三个动词顺序：**设计 → 理解 → 拥有**。"理解"位于中间，是产品差异化的枢纽。

## 2.4 产品最终形态

方寸最终由五个层级组成：

```text
                    方寸 Fangcun

           ┌───────────────────────────┐
           │        AI 篆刻师            │   自然语言 → 可编辑参数
           └───────────────────────────┘

           ┌───────────────────────────┐
           │        数字篆刻器            │   生成 / 编辑 / 印蜕 / 导出
           └───────────────────────────┘

           ┌──────────┬──────────┬─────┴────┐
           │ 篆书字典  │ 中国印谱  │ 篆刻学院  │   内容与知识层
           └──────────┴──────────┴──────────┘

           ┌───────────────────────────┐
           │      篆刻知识体系            │   术语 / 课程 / 图解 / 测验
           └───────────────────────────┘

           ┌───────────────────────────┐
           │     中国印章数据库           │   字形 / 历史印 / 风格 / 出处
           └───────────────────────────┘
```

最上层是用户看到的 AI 与设计工具，最底层是文字数据库、历史印章数据库、章法规则与篆刻知识。它们共同构成方寸真正的产品价值。

# 3. 品牌理念

## 3.1 品牌名称

**方寸**

"方寸"在中国传统文化中具有多层含义：

- 印章通常不过方寸；
- 方寸之地可以容纳姓名、身份、思想和审美；
- "方寸"亦可指人的内心；
- 与印章"小中见大"的艺术特征高度吻合。

英文名称：**Fangcun**。国际版保留拼音，不译作 *Square Inch*；副标题可用 **Chinese Seal Studio**。

## 3.2 Slogan

主 Slogan：

> **方寸之间，自有天地。**

可选品牌文案：

- 一印一世界。
- 刻字于石，留名于世。
- 为每一个名字，刻下一方天地。
- 千年印迹，一方新生。
- 认得一方印，读懂半部史。（**新增**，用于知识普及场景）

## 3.3 Logo

Logo 最简方案即"方寸"二字。同时制作一枚**「方寸」二字白文方印**作为主视觉标识——Logo 本身就是产品生成能力的最佳展示，且应当由产品自身的引擎生成、参数可追溯。

# 7. 首页

## 7.1 目标

首页不是产品介绍页，**首页本身就是生成器**。用户进入网站后应在 3 秒内理解：

> "这里可以生成中国古代印章。"

## 7.2 Hero

| 元素 | 内容 |
|---|---|
| 主视觉 | 大号「印」字 |
| Slogan | 方寸之间，自有天地。 |
| 输入框 | 输入你想刻下的文字 |
| Placeholder | 例如：清风明月 |
| 主 CTA | **生成我的印章** |
| 次入口 | 试试 AI 篆刻师 · 今日一印 · 我不懂篆刻，先看看（→ 学院） |

## 7.3 Hero 动效

首页动效不是装饰层，而是用运动解释“文字如何成为一枚印”。用户输入文字后：文字逐渐转变成篆书 → 章法线框归位 → 印面染上印泥 → 模拟真实盖印动画。

```text
楷字输入 → 篆字替换 → 章法聚合 → 石章落下 → 轻微震动 → 抬起 → 印蜕出现
```

首屏之后增加一段可跳过的滚动叙事“**一枚印如何诞生**”，依次展示字形、章法、刀感、印泥四层；滚动只控制演示进度，不劫持页面滚动，也不阻塞生成入口。

## 7.4 首页模块

| 区域 | 内容 | 说明 |
|---|---|---|
| Topbar | Logo、主导航、搜索、登录、开始生成 | 首页透明式，工具页实底 |
| Hero | 印、Slogan、输入框、生成按钮 | 输入即预览 |
| Live Seal | 默认示例印或用户输入预览 | 轻微印泥呼吸感 |
| Style Strip | 汉印 / 古玺 / 秦印 / 文人印 / 鸟虫 / 官印 | 悬停即时预览同一文字 |
| Why Fangcun | 章法 / 字形 / 印蜕三项差异化 | 真实前后对比，不用长文 |
| **今日印识** | 每日一条印章小知识 | **新增**，知识普及入口 |
| Content Entry | 今日一印、字典热门字、精选古印、入门课程 | 推动 SEO 与内容发现 |

| ID | 需求 | 优先级 | 版本 |
|---|---|---|---|

# 8. 印章生成器

路径：`/create`（快速）与 `/studio/:id`（专业）。这是整个产品最核心的功能。

## 8.1 快速生成模式

### Step 1 — 输入文字

> **知识渗透点**：每个风格 chip 悬停显示 30 字风格简介 + "了解更多"链接；每个滑块显示"文化语义"值（如"残损 35% / 微残"）。详见 [10.4](#104-随处可学l1-环境化学习)。

## 9.7 章法引擎

这是方寸最核心的技术能力之一。真正的印章不是普通 Grid Layout，系统需要理解：字数、字形结构、朱白、字间关系、边框关系、留白、中心平衡。

### 9.7.1 自动章法类型

以"清风明月"为例，系统可生成：

| 类型 | 特征 |
|---|---|
| 汉印式 | 四字田字格 |
| 古玺式 | 不规则布局 |
| 满白式 | 扩大文字占比 |
| 疏朗式 | 增加留白 |
| 文人式 | 字形大小不等 |
| 回文式 | 按传统印章阅读方向重新排列 |

MVP 需提供 **6 种自动章法**，V1 扩展到 **12 种**。

### 9.7.2 按字数推荐

| 字数 | 候选布局 |

| 1 | 居中 / 偏心古玺 |
| 2 | 纵排 / 横排 / 大小错落 |
| 3 | 右二左一 / 右一左二 / 三字纵排 |
| 4 | 田字格 2×2 / 回文 / 两列纵排 / 不等格古玺 |
| 5–8 | 多列动态列宽 / 混合 cell |

### 9.7.3 传统阅读方向

- 右上 → 左上 → 右下 → 左下
- 右列 → 左列
- 左列 → 右列
- 回文

普通用户默认**自动推荐**，专业模式允许修改。**每次切换阅读方向时，界面用箭头动画演示读序**（知识渗透点）。

## 9.9 印蜕模拟系统

真实盖印永远不是一个完美 SVG。因此方寸需要建立**印蜕引擎**，模拟真实印章在纸上的效果。

### 9.9.1 做旧参数

# 10. 印章知识普及体系

> **本章为 V2.0 新增的核心章节。**

## 10.1 为什么知识是产品功能而不是内容附属

一枚印章之所以"好"，原因往往是不可见的：为什么这四个字要这样排、为什么这条边要残、为什么这枚是白文。如果用户看不见这些原因：

- 他无法判断六个候选方案哪个更好，只能凭直觉乱点；
- 他不会觉得自己"做了一枚印"，只觉得"抽了一次卡"；
- 他没有理由再来第二次。

因此方寸的知识体系有三个产品目标：

| 目标 | 说明 | 对应指标 |
|---|---|---|
| **看得懂** | 用户能读出一枚印的朱白、字体、章法、时代 | 知识卡展开率、术语点击率 |
| **选得对** | 用户能为自己的用途选择合适的印 | 候选选中率、导出率 |
| **留得下** | 用户因为学到东西而回访 | 7 日回访率、课程完成率 |

## 10.2 知识体系三层结构

```text
┌──────────────────────────────────────────────────────┐
│  L3 主动探索  印章小百科 / 时间轴 / 字源演变 / 印库图解    │
├──────────────────────────────────────────────────────┤
│  L2 系统学习  篆刻学院 7 阶课程 / 练习 / 识印小测          │
├──────────────────────────────────────────────────────┤
│  L1 随处可学  术语浮层 / 参数解说 / 标签跳转 / AI 解释      │
└──────────────────────────────────────────────────────┘
                          ↑
                统一术语库 Glossary（单一事实来源）
```

三层共用同一份**术语库**：一个术语只写一次，在浮层、词条页、课程正文、AI 解释中复用。数据结构见 [TECH.md §20](TECH.md)。

### 10.5.1 误区纠正专栏（**新增**）

传统文化领域误传极多，纠错内容本身极具传播力。

| 常见误区 | 正确说明 |
|---|---|
| "篆刻就是刻篆书" | 篆刻是印章艺术的总称，字体不限于篆书（如元押、边款用楷行） |
| "印章都是方的" | 战国古玺形制极自由；圆、椭圆、随形、肖形均为传统形制 |
| "红字是正统，白字不正规" | 汉印以白文为主流；朱白与正统无关 |
| "印章 = 签名 = 法律效力" | 艺术印章不具备公章效力，混用有法律风险（见 [17.2](#172-合规检查器新增)） |
| "越残越有古意" | 残损是结果不是目的；过度残损破坏字法可读性 |
| "篆刻只要会写字就行" | 字法、篆法、章法、刀法四者缺一不可 |

# 11. AI 篆刻师

## 11.1 输入示例

> 我的网名叫"听雨"，希望做一枚比较孤寂、古朴的印章。

| 项目 | 结果 |
|---|---|
| 文字 | 听雨 |
| 推荐印式 | 圆印 / 小方印 |
| 文字体系 | 古玺 |
| 朱白 | 朱文 |
| 章法 | 两字纵排 |
| 边框 | 不规则细边 |
| 残损 | 35% |

随后直接生成多个方案。

## 11.2 品牌印章场景

> 帮我设计一枚适合个人博客 Logo 的"天眼"印章。

AI 理解产品属性、文字结构、视觉用途，输出：白文方印 / 小篆 / 两字纵排 / 强几何构成 / 低残损 / 适合 Logo 使用。

## 11.3 参数模型

内部将自然语言解析为结构化参数：

```json
{
  "text": "听雨",
  "era": "ancient_seal",
  "script": "gu_xi",
  "shape": "circle",
  "yin_yang": "yang",
  "layout": "vertical",
  "density": 0.55,
  "distress": 0.35,
  "border": "irregular"
}
```

**AI 的职责是理解需求并配置参数，而不是直接输出不可控的 AI 图片。**

## 11.4 交互状态

| 状态 | 界面 |
|---|---|
| 空状态 | 引导语"描述你想要的气质、用途或时代感" + 示例 chips |
| 解析中 | "正在理解用途 / 风格 / 章法"三段轻量进度 |
| 推荐结果 | 参数摘要 + 1–2 句理由 + 4–6 个方案 |
| 继续调整 | 支持"再古拙一点""改成适合 Logo""不要边框" |
| 异常 | 明确指出缺字、历史风格冲突或不支持的需求，并给可执行替代方案 |

推荐结果必须允许"查看参数"，把自然语言需求转换为可理解的 Seal DSL 摘要。

# 17. 合规、伦理与内容安全

> 本章为 V2.0 新增独立章节。原 V1.0 中分散在各处的伦理提示在此集中并强化。

## 17.1 三条红线

| 红线 | 说明 |
|---|---|
| 不得用于伪造 | 禁止生成、辅助生成政府机关公章、企业公章、财务专用章、发票章、证照类印鉴 |
| 不得复刻文物 | 印库的"以此风格生成"是抽取风格参数，不是复制原印 |
| 不得冒充他人 | 社区禁止以他人名义发布印章、冒充官方账号 |

## 17.2 合规检查器（**新增**）

| ID | 需求 | 优先级 | 版本 |
|---|---|---|---|
| FR-901 | 输入文字命中敏感词库（"公章""专用章""有限公司"+"章"等组合）时提示风险 | P0 | V1 |
| FR-902 | 生成结果与常见公章版式（圆形 + 五角星 + 环形字）高度相似时拦截并说明 | P0 | V1 |
| FR-903 | 拦截提示同时提供知识说明"为什么不能这样做"，链接 L6 课程 | P1 | V1 |
| FR-904 | AI 篆刻师收到此类请求时明确拒绝并解释 | P0 | V1.1 |
| FR-905 | 导出文件元数据标注"艺术用途，非法定印鉴" | P1 | V1 |
| FR-906 | 社区发布前进行同类检测 | P0 | V2 |

> 合规检查本身即是知识普及的一部分：大多数用户并不知道艺术印章与法定印鉴的边界，拦截时的解释是有效的教育时机。

## 17.3 文化表述规范

| 规范 | 说明 |
|---|---|
| 不宣称复刻大师 | 使用"某类历史篆刻语言""某时代风格特征"表述 |
| 不虚构历史 | 无出处的历史断言不上线 |
| 材质伦理 | 不将涉及珍稀动物制品的材质作为宣传卖点或默认选项 |
| 中立 | 不贬低任何流派或地域风格 |
| 出处可追溯 | 字形与历史印必须携带 source / license 元数据 |

## 17.4 数据与隐私

- 项目默认 private，公开需用户主动操作；
- 用户可导出与删除自己的全部数据；
- 用户上传的自定义 SVG（后期）必须经过 sanitizer。

# 23. 竞争壁垒与产品原则

## 23.1 五个长期壁垒

| # | 壁垒 | 内容 |
|---|---|---|
| 1 | **篆字数据库** | 历史字形、SVG Path、字形出处、时代、结构 |
| 2 | **章法算法** | 让文字真正符合传统篆刻逻辑 |
| 3 | **印蜕模拟算法** | 让数字矢量图产生真实盖印感 |
| 4 | **数字印谱** | 高质量、结构化的中国历史印章数据库 |
| 5 | **印章知识体系**（新增） | 结构化术语库 + 课程 + 图解 + 与引擎参数一一对应的解释层 |

如果第四项建成，方寸不仅是设计工具，也可以成为**中国印章数字档案馆**。

第五项的壁垒性在于：知识必须与引擎参数**一一对应**才有价值。竞品可以抄一篇科普文章，但抄不走"点击滑块就能看到对应传统概念"的结构化映射。

## 23.2 产品原则

> ### 传统，而不复古。
> ### 专业，而不晦涩。
> ### AI，而不失控。
> ### 数字，而有手作感。
> ### 简单生成，深度编辑。
> ### **能用，也要能懂。**（新增）

## 23.3 最核心的产品体验

第一次访问方寸的人：

打开网站 → 看到「方寸之间，自有天地。」→ 输入「清风明月」→ 点击「生成」→ 屏幕中央出现 6 枚不同风格的中国印章 → 点击其中一枚 → 进入编辑器 → 拖动「古拙」→ 拖动「残损」→ 切换「汉印」→ 点击「重新盖印」，每次印泥痕迹略有不同 → 最后点击 **导出 SVG**。

这一刻用户应该产生：

> "这不是普通印章生成器。"

而当他随手点开「白文」旁边那个小小的问号，看到一句解释时，他应该产生第二个念头：

> "原来是这样。"

这两个念头合起来，才是方寸最重要的产品体验。

# 24. 风险与开放问题

## 24.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 字形资产授权不清 | 法律风险，可能被迫下线 | 每个 Variant 强制 source / license；优先自绘与公有领域 |
| 章法算法效果不及预期 | 核心差异化落空 | MVP 用高质量模板 + 评分兜底，不依赖纯优化 |
| 知识内容准确性 | 文化产品的信任基础 | 出处强制、人工审校、专家顾问 |
| 知识体系投入产出不确定 | 资源错配 | 用 `knowledge_assisted_export` 验证核心假设 |
| 被用于伪造印鉴 | 严重合规风险 | 合规检查器（[17.2](#172-合规检查器新增)）+ 社区审核 |
| SVG 复杂度过高 | 导出文件过大、下游软件打不开 | path complexity budget + simplify |
| 生成结果同质化 | 用户"抽一次卡就走" | 候选多样性指标 + 风格参数分布 |
| 动效与 3D 反客为主 | 首屏变慢、编辑效率下降、传统文化表达游戏化 | 所有 3D 按需加载；动效不阻塞任务；克制材质与静态降级 |
